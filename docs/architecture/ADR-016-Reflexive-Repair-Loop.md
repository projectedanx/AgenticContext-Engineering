# ADR-016: Reflexive Repair Loop Architecture

**Status:** Proposed
**Date:** 2026-06-03
**Author:** VULCAN (Principal Staff Engineer / Vector-Unified Logical Computing Architect Node)

## Hickam_Orientation
The divergence between probabilistic generative outputs (System 1) and deterministic verifiability (System 2) dictates a necessity for a formal, self-correcting cognitive architecture. Traditional error handling treats failure as an exceptional state necessitating manual intervention. The Reflexive Repair Loop mandates the integration of active interdiction, automated feedback injection, and bounded self-correction directly into the agent’s execution lifecycle. This mitigates hallucination propagation and semantic saponification by establishing a "Deterministic Funnel."

## Contrastive_Delta
- **Previous State:** Agents operate in an open-loop configuration, relying on implicit context or human-in-the-loop debugging when symbolic boundaries are breached. Failures are discarded rather than metabolized into structural constraints.
- **Proposed State:** A dual-system, two-speed cybernetic control loop. System 1 generates candidate actions. System 2 intercepts and verifies these actions against Semantic Integrity Constraints (SICs) via static analysis, compilation, or symbolic solving. Violations trigger Reflexive Prompt Injection, repelling the latent space from failure coordinates.
- **Differential Impact:** Converts probabilistic volition into deterministically safe execution. Establishes an anti-fragile immune system (Epistemic Metabolism) by logging "Symbolic Scars," which immunize the system against repeated identical failure trajectories via Failure-Informed Prompt Inversion (F-IPI).

## Martensite_Metrics
- **Loop Escape Velocity:** Max 3 iterations per node before state lock.
- **Epistemic Escrow Trigger:** Confidence-Fidelity Divergence (CFD) > Safety Limit (dynamically scaling from 0.1 for state mutations to 0.8 for conceptual generation).
- **Scar Immunization Rate:** 100% of escrowed faults must generate a negative constraint block for future sessions.

## Pluriversal_Knowledge_Capsule

### 1. Phase-by-Phase Mechanics
The operational lifecycle operates as a Deterministic Funnel:
1.  **Hypothesis Generation (System 1):** The LLM proposes a candidate solution (SQL, AST mutation).
2.  **Symbolic Interdiction (System 2):** Deterministic verifiers (AST compilers, Z3 SAT solvers) intercept the payload.
3.  **Fault Detection:** If a Semantic Integrity Constraint (SIC) is violated, execution halts. A typed **Logic Violation Report (LVR)** is generated.
4.  **Reflexive Prompt Injection:** The LVR is converted into an explicit Negative Constraint and re-injected. This applies a vectorial repulsion force away from the failed coordinates.
5.  **Bounded Iteration:** Maximum of three targeted repair attempts.

### 2. Epistemic Escrow Safety Protocol
If the agent fails to resolve the logical or compilation failure after the third attempt, the system halts autonomous execution and locks the workspace state.
- **The Confidence-Fidelity Divergence (CFD) Trigger:** The escrow gate is triggered dynamically based on mathematical delta: $CFD = Confidence - Fidelity$.
- High confidence paired with low verified fidelity identifies the risk of **Confident Confabulation**, immediately locking the transaction before any state-altering action occurs.

### 3. Epistemic Metabolism: Capturing the "Symbolic Scar"
Unresolved violations that breach validation boundaries are logged as a **Symbolic Scar** in the **Scar Tissue Archive (STA)**.
- **Immunization via F-IPI:** Subsequent sessions query the STA using Case-Based Reasoning. Semantically similar tasks trigger Failure-Informed Prompt Inversion (F-IPI), proactively compiling past scars into project-level negative constraints.
